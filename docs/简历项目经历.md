## 项目经历一：快评 — 高并发本地生活服务平台

**技术栈**：SpringBoot · MyBatis-Plus · Redis · Redisson · RabbitMQ · Elasticsearch · MySQL · Guava RateLimiter

**项目描述**：基于 SpringBoot 开发的本地生活点评平台（类似大众点评），覆盖商户搜索、秒杀抢券、支付闭环、社交互动等核心场景，以 Redis 为核心深度优化高并发性能。

**个人职责与成果**：

- **秒杀系统**：基于 Redis + Lua 脚本实现库存预检、一人一单、异步下单的原子化流程，消除并发竞态；使用 Redisson 可重入分布式锁 + WatchDog 自动续期保证集群下的线程安全；通过 RabbitMQ 死信队列（TTL 30min）实现订单超时自动取消与库存恢复。单机秒杀 QPS [待测试]，订单异常率 [待测试]。

- **缓存与搜索**：基于 Cache Aside 模式设计多级缓存策略，针对穿透、击穿、雪崩分别采用「缓存空值」「逻辑过期+子线程异步重建」「随机过期+互斥锁」方案。集成 Elasticsearch + IK 分词器实现商铺搜索，支持关键词高亮与相关度排序。缓存命中率 [待测试]，搜索平均耗时 [待测试]。

- **系统防护与鉴权**：基于 AOP 实现接口分级限流（验证码 1 QPS / 登录 5 QPS / 秒杀 50 QPS）与熔断降级保护；设计双层拦截器架构（Token 刷新 + 登录校验），以 Redis 替代 Session 解决集群共享问题。

- **LLM 集成**：基于 LangChain + FastAPI 开发评价摘要 Agent，调用 LLM 对商铺评价进行情感分析与结构化摘要，集成到后端服务体系。

## 项目经历二：智能推荐 Agent — 面向快评业务的多轮对话推荐系统

**技术栈**：Python · LangGraph · LangChain · FastAPI · Redis · OpenAI API · Pydantic

**项目描述**：为点评平台开发基于 LLM 的智能推荐 Agent，采用 ReAct 模式实现多轮对话推荐，并设计自改进机制使其能够从历史推荐中持续优化策略。

**个人职责与成果**：

- **ReAct 工作流**：基于 LangGraph 构建多轮对话推荐流程（加载记忆→规划策略→调用工具→评估质量→生成回复→自我反思），集成 4 个业务工具（商铺查询、评价摘要、用户偏好、位置服务），支持条件分支与最多 3 轮重规划。当候选结果过多或过少时自动触发人工介入，确认后恢复执行。端到端延迟 [待测试]s，token 消耗 [待测试]。

- **自改进与经验库**：实现「聚合失败模式 → LLM 生成改进方案 → 回归验证」的闭环；设计 Playbook 经验库，从历史推荐中提取成功/失败经验并以结构化条目增量写入 prompt，替代无限制追加历史对话。迭代 [待测试] 轮后通过率提升 [待测试]%，人工介入频率降低 [待测试]%，prompt token 减少约 [待测试]%。

- **记忆与复盘**：设计 9 维用户偏好模型（类目/价格/环境/忌口等），基于 Redis 实现增量合并与 90 天过期；持久化每次推荐的完整过程（节点耗时、工具调用、决策理由），支持按用户和时间维度查询，用于失败复盘与模式挖掘。

- **评测体系**：设计 10 组测试用例集，覆盖通过率、迭代次数、人工介入率、响应时间、自评分数等 6 项指标，支持自改进前后的量化对比。

## 指标测试指南

> 所有 `[待测试]` 占位符需在本地环境实际运行后填写。以下为各指标的获取方式：

### 后端指标

| 指标 | 测试工具 | 方法 |
|------|----------|------|
| 秒杀 QPS / 异常率 | JMeter | 对 `/voucher-order/seckill/{id}` 并发压测，记录吞吐量与错误率 |
| 缓存命中率 | Redis `INFO stats` | 查看 `keyspace_hits / (keyspace_hits + keyspace_misses)` |
| 商铺查询响应时间 | JMeter / Postman | 对比有缓存 vs 无缓存（首次请求）的 `/shop/{id}` 耗时 |
| ES vs MySQL 搜索耗时 | 代码计时 | 同关键词分别走 ES `/shop/search` 和 MySQL LIKE，对比平均耗时 |

### Agent 指标

| 指标 | 测试工具 | 方法 |
|------|----------|------|
| 端到端延迟 | 代码计时 / `trajectory.nodeLogs[].durationMs` | 多次调用 `/agent2/recommend`，取 P50/P95/P99 |
| LLM token 消耗 | LangChain callback / OpenAI `usage` | 记录每次 LLM 调用的 `prompt_tokens + completion_tokens` |
| 通过率 / HITL 率 | Benchmark 框架 (`evaluator.py`) | 运行 `benchmark_runner.run_all()`，输出 `BenchmarkResult` |
| Playbook token 减少 | 对比实验 | 分别用全量历史 vs Playbook 注入，统计 prompt token 差值 |
| 自改进效果 | Benchmark before/after | 运行 N 轮 Self-Improvement 后重新 benchmark，对比通过率与 HITL 率 |
