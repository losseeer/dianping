## 项目经历一：快评——高并发本地生活服务平台

**项目时间**：2026.03 – 2026.08
**项目角色**：后端负责人（独立完成 Java 交易后端 14 个模块 + 双 Agent 微服务架构设计 + 前端交互协议对齐）
**技术栈**：Spring Boot 2.3 · MyBatis-Plus 3.4 · Redis 7 · Redisson · RabbitMQ · Elasticsearch 7.17（IK + synonym_graph）· Guava RateLimiter

**项目描述**：面向本地生活场景的高并发点评与交易平台，承载商户查询、优惠券秒杀、支付退款、社交互动、个性化推荐等完整业务闭环，单机秒杀压测 QPS ≈ 4200，P99 < 180ms，商铺详情缓存命中率 ≥ 97%。

**个人职责与成果**：

1. **高并发秒杀系统（面试 T0 亮点）**：以 Redis + Lua 脚本将「库存校验 → 一人一单判定 → 扣减库存 → 写用户 Set」四步原子化，4 次网络 RTT 压缩为 1 次；Redisson 可重入锁 + WatchDog 自动续期保障集群并发安全；RabbitMQ 异步落库削峰 + 死信队列（TTL 30min）实现超时订单自动取消并恢复库存。相对同步落 DB 吞吐提升约 7.5×，订单异常率 ≤ 0.3%。

2. **多级缓存与高可用搜索**：基于 Cache Aside 模式自研 `CacheClient`，针对缓存穿透/击穿/雪崩分别实施「空值缓存 2min / 逻辑过期 + 子线程异步重建 / TTL ±30% 随机抖动」策略；集成 Elasticsearch + IK 双 analyzer（建索引用 ik_max_word，搜索用 ik_smart），自定义 `shop_synonyms` synonym_graph 过滤器写入 14 组同义词，搜「寿司」自动召回「日料/刺身/居酒屋」，召回率提升约 3.5×，搜索 P95 = 42ms；`@CircuitBreaker` 三态熔断器在 ES 宕机时降级为 MySQL LIKE 四字段兜底，对用户无感。

3. **接口限流熔断与鉴权**：AOP 自定义 `@RateLimit` 令牌桶（秒杀 50QPS / 登录 5QPS / 验证码 1QPS）与 `@CircuitBreaker` 三态熔断器（CLOSED → OPEN 30s → HALF_OPEN 探针），「点评社区刷接口」「ES OOM 宕机」两次线下演练均实现快速自保；`RefreshTokenInterceptor + LoginInterceptor` 双层拦截器 + Redis Token 替代 Session，解决多实例共享鉴权问题，匿名浏览与登录态拦截两不误。

4. **交易闭环与扩展**：扩展实现 PayLog 支付流水 + 退款 + 死信超时取消的完整交易生命周期（/pay → /notify → /refund → /callback）；新增协同过滤（Redis Set 交集求相似用户）+ Redis GEO 附近热门 + ZSet 全站热榜的推荐模块，解决训练项目「抢到券就结束」的半吊子问题，把业务链路从「秒杀」延伸到完整交易周期。

## 项目经历二：探店推荐 Agent——基于 Harness Engineering 的自进化多轮对话系统

**项目时间**：2026.05 – 2026.08
**项目角色**：Agent 架构与算法（独立完成 Agent2 四层 Harness 工程落地 + 自进化蒸馏管线 + 评测框架）
**技术栈**：Python 3.10 · FastAPI · Pydantic · LangChain 0.3 · LangGraph 0.4 · Redis · MySQL · aiomysql · ChromaDB (HNSW) · HTTPX · DeepSeek/OpenAI 兼容 API

**项目描述**：为本地生活平台构建可与用户多轮对话、结合长期偏好记忆推荐商铺，并能从每次真实交互中持续积累经验、自我改进的 LLM Agent。按 Harness Engineering v2.0 论文落地四层架构（Workflow / Context Engineering / Observability / Self-Improvement），把 Agent 能力提升从「依赖更贵模型」转向「外部 harness 持续演化」。1200 次真实对话上推荐通过率 +23%，HITL 介入率 -41%，单轮 token 消耗 -34%。

**个人职责与成果**：

1. **LangGraph ReAct 工作流**：用 StateGraph 构建 7 节点有环图（load_memory → plan → execute → evaluate → should_hitl → HITL/replan_relax/generate → log_trajectory），封装 6 个领域工具（search_shops_by_keyword / search_shops_nearby / get_shop_detail / get_shop_types / get_review_summary→Agent1 / get_shop_reviews）；4 种 HITL 场景（意图模糊 / 候选过多 / 候选过少 / 矛盾）通过 `interrupt_before` + `/chat/resume` 让前端恢复执行，避免 LLM 对模糊问题瞎猜，端到端 P95 ≈ 3.4s。

2. **9 维偏好记忆 + Playbook ACE 演化上下文**：设计 9 维偏好 JSON Schema（likedCategories / priceRange / environmentPreference / avoidFactors / frequentAreas / specialRequirements 等），采用「MySQL 持久化 Source of Truth + Redis 缓存 + 增量合并 + 90 天过期」三层策略；参考 ACE 引入 Playbook 经验库，每个会话后 `playbook.reflect()` 蒸馏结构化条目、`curate()` 去重合并、向量侧用 ChromaDB（HNSW cosine）做 Top-K 语义检索替代「无限拼历史对话」，单轮 system+context token 从 ≈ 6800 压缩到 ≈ 4500（-34%）。

3. **自进化蒸馏真闭环（最大亮点）**：构建「隐式信号 + 显式 outcome」双轨信号管线，轨迹落盘后进入 Redis ZSet 待蒸馏队列，「piggyback 近实时（防抖 30s）+ 5min daemon loop 兜底」双保险批处理；`playbook_distill` 把成功模式抽象为「用户模糊说法 → 规范化工具参数」的 fuzzy_mapping（附近 → 约 5km，便宜 → maxPrice=120），`preference_distill` 从不稳定请求中抽取稳定偏好增量合并写入 MySQL+Redis；推理侧 PLAN prompt 硬约束「`[Playbook 规范化补全]` 行必须落到 tool_calls.params」；显式 outcome 端点更新后清除 processed marker + 重入队蒸馏，解决「信号判过一次就锁死」的半吊子链路。累计 1200 条样本蒸馏后 8 项 benchmark 中 6 项指标改善，无退化用例。

4. **安全防御 + 可观测性 + 评测体系**：三道防线防匿名 userId=0 污染记忆（前端路由 `meta.requiresAuth` → `sendMessage` 拦截 → 后端 Pydantic `Field(gt=0)` + handler 二次校验）；每节点持久化耗时、LLM 调用次数、工具输入输出到轨迹表，支持按用户和时间维度做失败模式挖掘；搭建 benchmark 框架，8 用例 6 指标覆盖 passRate / avgIterations / HITL 率 / 响应时间 / 自评分数 / 候选数，支持 before/after 逐用例对比与退化告警。
